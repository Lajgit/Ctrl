# 存珠机 Android 与控制板通信协议 V0.1

本文定义存珠机 Android App 与存珠控制板之间的串口通信协议。协议采用固定 14 字节帧格式，字段功能与售珠机协议保持一致，仅通过 `Code1` 方向码区分通信方向，并重新定义存珠机业务 `Code2`。

- 串口：`/dev/ttyS5`
- 默认波特率：`115200`
- 数据格式：`8N1`
- 帧长度：固定 `14` 字节
- 字节序：`Data1..Data4` 中的多字节业务数据使用大端；`CRC16` 低字节在前
- 校验：`CRC16/MODBUS`，多项式 `0xA001`，初值 `0xFFFF`
- CRC 覆盖范围：`Byte0..Byte10`
- CRC 不覆盖：`Byte11..Byte13`

## 1. 固定帧格式

| Byte | 字段 | 说明 |
| ---: | --- | --- |
| 0 | Head | 固定 `0xAA` |
| 1 | ResendID | 首发 `0`，重发递增；同一业务帧重发时 `ID` 不变 |
| 2 | ID | `frameId`，线路 echo 和 TerminalAck 使用 |
| 3 | Code1 | 方向码：`0x00` 控制板到 Android，`0x01` Android 到控制板 |
| 4 | Code2 | 功能码 |
| 5 | Data1 | 大端业务数据 |
| 6 | Data2 | 大端业务数据 |
| 7 | Data3 | 大端业务数据 |
| 8 | Data4 | 大端业务数据 |
| 9 | ACKbyte | `0x00` 普通业务帧；`0x01` 表示接收方对原帧 echo/确认 |
| 10 | ExpandCode | 结果码/故障码 |
| 11 | CRC16_L | CRC16 低字节 |
| 12 | CRC16_H | CRC16 高字节 |
| 13 | Tail | 固定 `0x55` |

## 2. Code1 方向码

| Code1 | 方向 |
| ---: | --- |
| `0x00` | 控制板 → Android |
| `0x01` | Android → 控制板 |

## 3. ACK echo 规则

普通业务帧：

```text
ACKbyte = 0x00
```

ACK echo 帧：

```text
ACKbyte = 0x01
```

ACK echo 字段规则：

| 字段 | 规则 |
| --- | --- |
| `ResendID` | 回显原帧 ResendID |
| `ID` | 回显原帧 ID |
| `Code1` | 使用自己的发送方向 |
| `Code2` | 回显原帧 Code2 |
| `Data1..Data4` | 回显原帧业务数据 |
| `ACKbyte` | 固定 `0x01` |
| `ExpandCode` | 填处理结果码，成功 `0x00` |

ACK echo 帧不再要求对方继续 ACK，避免确认帧死循环。

## 4. Code2 功能码

| Code2 | 名称 | 方向 | 是否需要 ACK echo | 说明 |
| ---: | --- | --- | --- | --- |
| `0x10` | `START_COLLECT` | Android → 控制板 | 是 | 开始收珠 |
| `0x11` | `STOP_COLLECT` | Android → 控制板 | 是 | 停止收珠 |
| `0x12` | `STATUS` | 双向 | 否 | Android 查询状态；控制板上报状态 |
| `0x13` | `CLEAR_FAULT` | Android → 控制板 | 是 | 清故障/复位业务状态 |
| `0x14` | `HEARTBEAT` | 双向 | 否 | Android ping，控制板 pong |
| `0x20` | `COUNT_CHANGED` | 控制板 → Android | 否 | 收珠计数变化 |
| `0x21` | `COLLECT_FINISHED` | 控制板 → Android | 是 | 收珠结束终态 |
| `0x22` | `FAULT_EVENT` | 控制板 → Android | 是 | 故障终态/异常事件 |
| `0x23` | `BOARD_BOOT` | 控制板 → Android | 否 | 控制板启动/复位上报 |

## 5. Android → 控制板

### 5.1 `0x10 START_COLLECT` 开始收珠

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x01` |
| `Code2` | `0x10` |
| `ACKbyte` | `0x00` |
| `ExpandCode` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1..Data2` | `maximumQuantity`，uint16，大端 |
| `Data3..Data4` | `sessionTimeoutSeconds`，uint16，大端 |

控制板收到后立即回 ACK echo。ACK echo 的 `ExpandCode=0x00` 表示接受；非 `0x00` 表示拒绝开始收珠。

### 5.2 `0x11 STOP_COLLECT` 停止收珠

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x01` |
| `Code2` | `0x11` |
| `ACKbyte` | `0x00` |
| `ExpandCode` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1` | stopReason |
| `Data2..Data4` | 保留，填 `0x00` |

stopReason：

| 值 | 含义 |
| ---: | --- |
| `0x00` | Android 主动停止 |
| `0x01` | MQTT 会话超时 |
| `0x02` | 用户取消 |
| `0x03` | 平台取消 |
| `0x04` | 故障处理停止 |

控制板收到后先回 ACK echo，然后停止电机，最终上报 `0x21 COLLECT_FINISHED` 或 `0x22 FAULT_EVENT`。

### 5.3 `0x12 STATUS` 查询状态

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x01` |
| `Code2` | `0x12` |
| `Data1..Data4` | `0x00 0x00 0x00 0x00` |
| `ACKbyte` | `0x00` |
| `ExpandCode` | `0x00` |

控制板回复一帧 `0x12 STATUS` 状态上报，不需要额外 ACK echo。

### 5.4 `0x13 CLEAR_FAULT` 清故障/复位业务状态

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x01` |
| `Code2` | `0x13` |
| `ACKbyte` | `0x00` |
| `ExpandCode` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1` | resetType |
| `Data2..Data4` | 保留，填 `0x00` |

resetType：

| 值 | 含义 |
| ---: | --- |
| `0x00` | 只清故障 |
| `0x01` | 清故障并清零本次计数 |
| `0x02` | 复位业务状态，不复位 MCU |
| `0x03` | 软复位 MCU，预留，默认先不用 |

控制板收到后回 ACK echo。

### 5.5 `0x14 HEARTBEAT` 心跳 Ping

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x01` |
| `Code2` | `0x14` |
| `Data1..Data4` | `0x00 0x00 0x00 0x00` |
| `ACKbyte` | `0x00` |
| `ExpandCode` | `0x00` |

控制板回复 `0x14 HEARTBEAT`，携带当前状态、计数和故障码。

## 6. 控制板 → Android

### 6.1 `0x12 STATUS` 状态上报

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x00` |
| `Code2` | `0x12` |
| `ACKbyte` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1` | currentState |
| `Data2..Data3` | actualQuantity，uint16，大端 |
| `Data4` | sensorState |
| `ExpandCode` | 当前故障码，无故障填 `0x00` |

### 6.2 `0x14 HEARTBEAT` 心跳 Pong

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x00` |
| `Code2` | `0x14` |
| `ACKbyte` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1` | currentState |
| `Data2..Data3` | actualQuantity，uint16，大端 |
| `Data4` | sensorState |
| `ExpandCode` | 当前故障码，无故障填 `0x00` |

### 6.3 `0x20 COUNT_CHANGED` 计数变化

控制板每确认 1 颗珠后上报。

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x00` |
| `Code2` | `0x20` |
| `ACKbyte` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1..Data2` | actualQuantity，uint16，大端 |
| `Data3` | currentState，通常 `0x01` |
| `Data4` | sensorState |
| `ExpandCode` | 正常填 `0x00` |

`0x20` 不强制 Android ACK。中间计数帧允许丢失，最终以 `0x21 COLLECT_FINISHED` 或 `0x22 FAULT_EVENT` 的 actualQuantity 为准。

### 6.4 `0x21 COLLECT_FINISHED` 收珠结束

这是终态帧。Android 收到后必须回 ACK echo，并上报 MQTT `command-result`。

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x00` |
| `Code2` | `0x21` |
| `ACKbyte` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1..Data2` | actualQuantity，uint16，大端 |
| `Data3` | finishReason |
| `Data4` | finalState，通常 `0x00` |
| `ExpandCode` | 结果码，正常 `0x00` |

finishReason：

| 值 | 含义 |
| ---: | --- |
| `0x00` | Android 主动停止 |
| `0x01` | 达到 maximumQuantity |
| `0x02` | 会话超时结束 |
| `0x03` | 控制板判断无珠/自然结束 |
| `0x04` | 人工/维护结束 |

控制板未收到 ACK echo 时，建议重发 `0x21`：同一个 `ID` 不变，`ResendID` 递增，最多重发 3 次。

### 6.5 `0x22 FAULT_EVENT` 故障上报

这是异常终态帧。Android 收到后必须回 ACK echo。

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x00` |
| `Code2` | `0x22` |
| `ACKbyte` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1..Data2` | 故障发生时已确认 actualQuantity，uint16，大端 |
| `Data3` | currentState，通常 `0x02` |
| `Data4` | sensorState |
| `ExpandCode` | 故障码 |

控制板未收到 ACK echo 时，建议重发 `0x22`：同一个 `ID` 不变，`ResendID` 递增，最多重发 3 次。

### 6.6 `0x23 BOARD_BOOT` 控制板启动/复位上报

| 字段 | 值 |
| --- | --- |
| `Code1` | `0x00` |
| `Code2` | `0x23` |
| `ACKbyte` | `0x00` |

| 字节 | 含义 |
| --- | --- |
| `Data1` | firmwareMajor |
| `Data2` | firmwareMinor |
| `Data3` | resetReason |
| `Data4` | currentState |
| `ExpandCode` | 当前故障码，无故障填 `0x00` |

resetReason：

| 值 | 含义 |
| ---: | --- |
| `0x00` | 上电启动 |
| `0x01` | 看门狗复位 |
| `0x02` | 软件复位 |
| `0x03` | 异常复位 |
| `0x04` | 手动复位 |

## 7. currentState 状态码

| 值 | 名称 | 含义 |
| ---: | --- | --- |
| `0x00` | IDLE | 空闲 |
| `0x01` | COLLECTING | 收珠中 |
| `0x02` | FAULT | 故障 |
| `0x03` | STOPPING | 正在停止 |
| `0x04` | MAINTENANCE | 维护 |
| `0x05` | SELF_TEST | 自检 |

Android 上报平台状态时映射如下：

| 控制板状态 | MQTT runningStatus |
| --- | ---: |
| IDLE | `0` |
| COLLECTING | `6` |
| FAULT | `2` |
| MAINTENANCE | `3` |

## 8. sensorState 位定义

| bit | 含义 |
| ---: | --- |
| bit0 | 入珠光眼遮挡 |
| bit1 | 计数/确认光眼遮挡 |
| bit2 | 电机运行中 |
| bit3 | 珠仓满/满珠检测 |
| bit4 | 门控/急停触发 |
| bit5 | 预留 |
| bit6 | 预留 |
| bit7 | 预留 |

## 9. ExpandCode 结果码/故障码

| 值 | 名称 | 含义 |
| ---: | --- | --- |
| `0x00` | OK | 成功/无故障 |
| `0x01` | BUSY | 忙，正在收珠 |
| `0x02` | PARAM_INVALID | 参数错误 |
| `0x03` | STATE_INVALID | 状态不允许 |
| `0x04` | CRC_ERROR | CRC 校验错误 |
| `0x05` | UNKNOWN_CODE2 | 未知功能码 |
| `0x06` | NOT_READY | 控制板未就绪 |
| `0x07` | SENSOR_ERROR | 光眼/传感器异常 |
| `0x08` | TIMEOUT | 超时 |
| `0x09` | MOTOR_ERROR | 电机异常 |
| `0x0A` | JAM | 卡珠/堵转 |
| `0x0B` | EMERGENCY_STOP | 急停/门控 |
| `0x0C` | STORAGE_FULL | 珠仓满 |
| `0x0D` | DUPLICATE_ACCEPTED | 重复帧已处理，返回上次结果 |
| `0xFF` | UNKNOWN | 未知错误 |

## 10. 正常收珠流程

```text
Android → 控制板：0x10 START_COLLECT，maximumQuantity=N，timeout=T
控制板 → Android：0x10 ACK echo，ExpandCode=0x00
控制板 → Android：0x12 STATUS，COLLECTING
控制板 → Android：0x20 COUNT_CHANGED，actualQuantity=1
控制板 → Android：0x20 COUNT_CHANGED，actualQuantity=2
...
控制板 → Android：0x21 COLLECT_FINISHED，actualQuantity=N
Android → 控制板：0x21 ACK echo，ACKbyte=0x01
Android → MQTT：command-result，actualQuantity=N
```

## 11. 故障流程

```text
Android → 控制板：0x10 START_COLLECT
控制板 → Android：0x10 ACK echo，ExpandCode=0x00
控制板 → Android：0x20 COUNT_CHANGED，actualQuantity=5
控制板 → Android：0x22 FAULT_EVENT，actualQuantity=5，ExpandCode=0x0A JAM
Android → 控制板：0x22 ACK echo，ACKbyte=0x01
Android → MQTT：command-result failed，actualQuantity=5
```

## 12. Android 端当前实现范围

当前 Android 端已实现：

1. 构造 `START_COLLECT`、`STOP_COLLECT`、`STATUS`、`CLEAR_FAULT`、`HEARTBEAT` 帧。
2. 解析控制板 `ACK echo`、`STATUS`、`COUNT_CHANGED`、`COLLECT_FINISHED`、`FAULT_EVENT`、`BOARD_BOOT`。
3. 收到 `COLLECT_FINISHED` 或 `FAULT_EVENT` 后回 ACK echo。
4. `COLLECT_FINISHED` 转为硬件成功结果，`FAULT_EVENT` 转为硬件失败结果。
5. `COUNT_CHANGED` 仅更新本地真实计数，不直接上报 MQTT 终态。

当前 Android 端尚未实现：

1. 对串口粘包中的多帧逐帧处理。当前优先解析缓冲区内第一帧完整 14 字节帧。
2. Android 发送命令后的超时重发机制。当前由上层收珠会话超时保护。
3. 控制板启动 `BOARD_BOOT` 后的自动清故障或自动查询策略。
