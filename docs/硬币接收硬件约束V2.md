# V2 硬币接收硬件约束

当前控制板代码能够读取投币脉冲，但仓库中没有找到可验证的硬币接收器 inhibit/enable 输出实现。

因此 V2 默认策略是：

```text
纸币配置：可按平台配置应用
硬币配置：控制板拒绝启用，整份现金配置应用失败，现金保持关闭
```

对应定义：

```c
#define CASH_ACCEPT_BANKNOTE_MASK (1U << 0)
#define CASH_ACCEPT_COIN_MASK 0U
```

不能把“能够读取硬币脉冲”等同于“能够安全开启或关闭投币器”。平台协议要求只有完整现金配置持久化并成功应用后才允许接收现金；没有硬件 inhibit 输出时，App 和控制板无法保证配置禁用、异常、无珠、断网或人工复核期间阻止硬币进入。

量产启用硬币前必须完成：

1. 确认投币器 inhibit/enable 引脚、电平和上电默认状态；
2. 在硬件原理图中接入可控输出，并保证 MCU 复位时默认禁止收币；
3. 提供 `CashHardware_SetCoinEnable(bool enable)` 的强实现；
4. 将 `CASH_ACCEPT_COIN_MASK` 恢复为 `(1U << 1)`；
5. 验证配置启用、禁用、无珠、紧急停止、App 退出和 MCU 重启时的物理收币状态；
6. 验证每枚硬币只生成一个稳定现金事件，不直接启动出珠。

在上述条件完成前，不允许通过软件假定硬币接收已经成功启用。
