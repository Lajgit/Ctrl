# V2.1 三线硬币器硬件约束

当前硬币器只有：

```text
12V
GND
投币脉冲
```

没有 inhibit/enable 控制线，因此控制板无法通过软件阻止硬币进入。

V2.1 的实际策略：

```text
纸钞机：可通过ICT命令启用或关闭
硬币器：始终监听脉冲、始终记录、始终上报
```

对应定义：

```c
#define CASH_ACCEPT_BANKNOTE_MASK (1U << 0)
#define CASH_ACCEPT_COIN_MASK     (1U << 1)
```

`CashAcceptance_Disable()` 的含义是关闭纸钞机；硬币状态位仍保持1。软件不得因为平台配置关闭、设备无珠、MQTT断线或电机执行中而丢弃硬币脉冲，否则会产生“用户已投币但平台无记录”的资金差错。

## 连续投币

控制板使用16项掉电现金队列：

```text
每个有效脉冲
→ 生成独立现金序号
→ 保存本笔金额
→ Android确认后推进下一笔
```

当前代码按：

```text
1个有效脉冲 = 1元 = 100分
```

若投币器配置为多脉冲表示不同面额，必须增加脉冲组结束时间和“脉冲数→金额”映射，不能继续把每个脉冲单独解释为1元。

## 无法物理关闭带来的约束

1. 设备断网时硬币仍可能进入；
2. Android异常时控制板队列最多缓存16笔；
3. 队列满后无法物理退回后续硬币，只能置溢出故障；
4. 平台必须监控现金队列和设备在线状态；
5. 最稳妥的量产硬件仍应增加投币器 inhibit、供电开关或可控闸门。

在当前三线结构下，“关闭现金接收”只能可靠关闭纸币，不能可靠关闭硬币。
