# 设备报到自动登记增量说明

## 变更背景

本次只改“首次报到”链路，不改激活、凭证恢复、MQTT 登录逻辑。

平台新增了可配置的首次报到自动登记能力：

- 开启后，设备首次报到时带上 `identityPublicKey`，平台先验签，再自动登记身份公钥。
- 关闭后，仍走原来的预登记模式，未登记设备会返回 `设备身份未登记`。

## 设备端需要改什么

### 1. 报到调用改成传 `KeyPair`

原来：

```java
lifecycle.enroll(identityPrivateKey, firmwareVersion, apkVersion);
```

现在：

```java
lifecycle.enroll(identityKeyPair, firmwareVersion, apkVersion);
```

批次自动认领也一样：

```java
lifecycle.enrollWithBatch(identityKeyPair, firmwareVersion, apkVersion, batchNo, batchSecret);
```

### 2. 报到请求会自动携带公钥

SDK 会自动把 `identityPublicKey` 带到 `/api/device/enroll`。

设备端不需要自己拼这个字段，但要确保传入的是同一组密钥对。

### 3. 激活接口不变

激活仍然使用私钥：

```java
lifecycle.activateWithIdentity(identityKeyPair.getPrivate(), firmwareVersion, apkVersion);
```

### 4. 需要重新打包

这次涉及 SDK 代码变更，需要重新打包并替换设备侧依赖：

- `xiaoda-device-sdk-0.1.0.jar`

`xiaoda-device-mqtt` 和 `xiaoda-device-hardware` 这次没有改动。

## 平台侧开关

平台配置项：

```yaml
device:
  identity:
    auto-registration-enabled: true
```

- `true`：首次报到自动登记
- `false`：恢复原来的预登记模式

## 行为边界

- 已登记设备：仍按已登记公钥验签，不会自动换钥。
- 未登记设备且自动登记关闭：返回 `设备身份未登记`。
- 未登记设备且自动登记开启：首次报到成功后自动落库。
- 激活和凭证恢复流程不变。

## 建议联调顺序

1. 设备生成并保存 `KeyPair`
2. 调用 `enroll(identityKeyPair, ...)`
3. 商户认领或批次自动认领
4. 调用 `activateWithIdentity(identityKeyPair.getPrivate(), ...)`
5. 收到 MQTT 凭证后原子保存
