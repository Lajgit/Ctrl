# 平台统一现金与出珠架构 V2

## 目标

V2 将“收款事实”和“物理出珠授权”彻底分离：

```text
现金/扫码/会员/核销产生业务事实
→ 平台创建或确认订单
→ 平台统一下发 dispense_marbles
→ 设备执行真实物理动作
```

设备不得根据现金金额、支付页面或本地规则自行决定出珠数量。

## 分层

### 1. 设备生命周期层

```text
ActivationManager
DeviceSdkManager
SdkCredentialStore
```

负责报到、认领、激活、MQTT 凭证原子替换和日常 reactivate。

### 2. MQTT 传输层

```text
MqttManager
```

只负责连接、先订阅、接收原始 payload 和发布。业务确认不能使用 MQTT PUBACK 替代。

### 3. SDK 协议层

```text
SdkCommandDecoder
DeviceMqttCommandCodec
DeviceHardwareCommandMapper
DeviceCommandResultCodec
```

负责 Topic、deviceNo、命令类型、参数、operationNo、operationToken、有效期、硬件请求和命令结果的强类型转换。

### 4. 业务状态机

```text
DeviceCommandManager
```

负责：

- 现金配置完整校验和应用；
- 现金事实持久化与重发；
- messageId 幂等；
- ACK/终态 outbox；
- 物理动作启动前持久化；
- 进程恢复时禁止重复启动；
- 平台业务确认后删除 outbox。

### 5. 本地持久化层

```text
DeviceCommandStore
SQLite: gouzhu_platform_control_v2.db
```

旧 SharedPreferences 业务状态不迁移。

### 6. 控制板传输层

```text
SerialManager
/dev/ttyS5
14 字节协议 V2
```

负责帧、CRC、线路 ACK 和控制板 Bootloader，不负责业务数量决策。

### 7. 控制板硬件执行层

```text
CommunicateTask
CtrlTask
KeyTask
FlashTask
InterruptTask
MesgTask
```

控制板只保存硬件事实：库存、待确认现金事实、亮度和必要状态；不保存本地价格、余额、订单或欠吐队列。

## 持久化顺序

### 现金

```text
控制板检测现金不可逆入箱
→ 控制板写 Flash
→ 控制板持续重发 CashAccepted
→ App 在 SQLite 事务写现金事件 + cash outbox
→ App 发送 CashEventStored
→ 控制板删除 pending cash
→ App 发布 report/cash-event
```

### 出珠

```text
SDK 校验 dispense_marbles
→ App 写完整命令和“可能启动”状态
→ App 写 SDK ACK outbox
→ App 发布 ACK
→ App 发送 ttyS5 DispenseStart
→ 控制板发送 Started/Progress/Terminal
→ App 保存 Started/Terminal
→ App 发送 BoardEventStored
→ App 写 SDK terminal outbox
→ App 发布真实 actualQuantity
```

硬件光眼映射固定为：PD4 / EXTI4 → 出珠光眼 → HoolleOutput_Pin → Hardware_OnDispensePulse；PD3 / EXTI3 → 存珠光眼 → CardFeedback_Pin → Hardware_OnCollectPulse。

## 失败原则

- 未应用现金配置：关闭现金；
- 配置非法：关闭现金；
- 找零开启：拒绝配置；
- 现金档位不匹配：保留事实，关闭现金，转异常；
- 指令重复：只重发已保存结果；
- 物理结果未知：不伪造终态，不重启电机，转人工；
- 无珠或光眼超时：上报真实部分数量，关闭现金；
- 平台响应 unknown：重发完全相同现金 payload；
- MQTT PUBACK：不删除业务 outbox。
